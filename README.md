# AI-NetTune

**基于 LLM 意图驱动的多模态无线网络智能监测与辅助分析平台**

面向**网络测试与优化人员**的多接入点无线组网（5G 现网 / 校园 / 商场等）场景 Web 智能监测平台：方便测试人员开展测试与网络优化并给出专业建议——支持自然语言提问，快速定位故障、输出处置恢复建议；融合位置感知与电磁频谱预测，提前预警；以**文本、图表、地图、拓扑及序列态势图**多模态呈现专业网络状态（非专业用户亦可借此看懂网络状态）。

---

## 项目简介

本项目将大语言模型（LLM）智能体意图驱动思想迁移至无线网络监测领域，主受众为**网络测试与优化人员**：

* **数据层**：支持仿真数据生成与 CSV 导入，模拟多接入点、多用户无线组网监测场景（11 维数据字典，含网络状态标签，见 [docs/data_dict.md](docs/data_dict.md)）；后续扩展 AP/UE 坐标字段以支撑拓扑可视化；

* **智能层**：通信 KPI 语义层将 RSRP、SINR、吞吐量等专业指标翻译为自然语言；多 KPI 联合研判引擎结合通信专业知识输出**可解释**的故障结论（覆盖故障 / 网络拥塞 / 边缘弱用户）与**处置恢复建议**；融合历史与实时数据预测未来电磁频谱态势并**提前预警**；采用 **Model-free 免建模架构**——不依赖信道与传播模型，直接以历史与实时数据驱动预测与优化，规避建模误差；

* **交互层**：用户通过自然语言提问，即可完成数据查询、故障研判、报告导出，输出**文本、图表、地图、拓扑及序列态势图多模态**研判结果；

* **可靠性**：大模型仅负责语义理解，数据运算交由确定性工具执行，规避幻觉问题；大模型 API 不可用时，表单查询、告警、可视化等核心功能可降级完整使用。

## 项目价值

不止"看得见"，更要"能处置、有效益"：

* **快速定位**：多 KPI 联合研判定位故障区域（覆盖异常 / 拥塞 / 边缘弱信号），输出证据链与处置恢复建议，缩短排障时间；

* **提前预警**：基于历史与实时数据预测未来电磁频谱态势，故障发生前预警，变"事后排障"为"事前防范"；

* **降本增效**：减少故障定位与处置时长、降低网络运维人力成本，面向运营商 / 校园 / 商场网维场景可落地。

## 功能特性

* ✅ 通信 KPI 可视化（折线图 / 信号热力图 / 网络拓扑图 / 频谱地图）

* ✅ **多接入点拓扑图**：基站（AP）与用户（UE）位置分布、连接关系；点选 UE 查看信号 / 干扰 / 速率参数（借鉴 radiomap.online 的 Cell-Free 拓扑可视化风格）

* ✅ **区域电磁频谱视图**：区域信号质量热力分布（各区域频谱态势一览）

* ✅ **真实 vs 预测对比图**：历史真实帧与预测帧并排对比（Signal / Interference / Rate）+ MAE / RMSE 误差指标（🚧 随时序预测落地）

* ✅ 区域信号质量预测与信号导航指引（位置感知 + 电磁频谱分析），故障**提前预警**

* ✅ 监测→定位→处置闭环：快速定位故障区域，输出处置恢复建议，降低运维成本

* 🚧 时序预测：基于历史与实时监测数据，以**机器学习模型（Prophet / LSTM）**预测未来信号质量（电磁频谱态势预测）

* ✅ 多 KPI 联合故障研判，输出 "故障类型 → 证据链 → 原因 → 处置建议"

* ✅ 自然语言对话式监测（LLM 意图识别）+ 多模态输出

* ✅ 分析报告导出

* ✅ 仿真数据生成 + CSV 导入

* 🚧 React + TypeScript 前端（前后端联调中）

## 快速开始

### 后端（当前已可运行）

```
# 1. 安装依赖
python -m pip install fastapi uvicorn pandas

# 2. 启动服务（局域网联调用 0.0.0.0）
python -m uvicorn main:app --reload --host 0.0.0.0
```

浏览器打开 [http://localhost:8000/docs](http://localhost:8000/docs) 查看 Swagger 接口测试面板。

> 接口 1/2/3 已接入唐苗仿真数据集（`data/network_data.csv`，12960 条），返回真实查询与多KPI研判结果；接口 4 报告生成为占位，第 3 周接入。
>
> 时序预测（接口 5）开发中：需先把仿真数据扩展为**多日时间跨度**（当前 `network_data.csv` 仅 2026-01-01 单日，无法支撑"历史 → 未来"的预测演示）。

### 前端（联调中）

```
cd frontend
npm install
npm run dev
```

# 数据字典 - 网络仿真实时序数据集

> 说明：仿真逻辑参考Cell-Free无蜂窝MIMO仿真思路，采用固定AP点位+随机移动UE，对数距离路径损耗模型生成信号，保留原有全部字段，新增坐标字段与扩展辅助字段，输出CSV时序数据集。

|字段名|数据类型|单位|说明|
| ---- | ---- | ---- | ---- |
|timestamp|string|-|时间戳，连续3天时序，用于时序可视化、历史态势预测|
|ap_id|string|-|接入点AP编号，如AP-01，固定AP设备|
|ap_x|float|米|AP设备平面X坐标，同一个AP固定不变|
|ap_y|float|米|AP设备平面Y坐标，同一个AP固定不变|
|user_id|string|-|用户终端UE编号|
|ue_x|float|米|用户终端平面X坐标，随时间变化模拟用户移动|
|ue_y|float|米|用户终端平面Y坐标，随时间变化模拟用户移动|
|rsrp|float|dBm|接收信号功率，基于距离路径损耗模型计算，距离越远信号越弱|
|sinr|float|dB|信干噪比，考虑多AP之间干扰计算得到|
|throughput|float|Mbps|吞吐量，基于香农容量公式，由SINR计算|
|latency|float|ms|网络时延，随PRB资源负载动态变化|
|packet_loss|float|%|丢包率，高负载场景下数值上升|
|prb_usage|float|%|无线PRB资源占用率，0~100|
|scenario|string|-|场景类型：校园 / 商场 / 体育馆|
|network_status|string|-|网络状态标签：normal(正常)、weak_coverage(弱覆盖，rsrp<-110)、congestion(拥塞，prb_usage>85且packet_loss>5)|
|retransmission_count|int|次|单位时间内数据重传次数，与丢包率正相关，用于故障原因辅助判断|
|traffic_demand|float|Mbps|用户侧业务需求吞吐量，始终≥实际吞吐量，用于区分低需求与网络受限|
|active_users|int|个|当前AP下的活跃用户总数，反映基站接入负载压力|


> **拓扑坐标字段（规划）**：为支撑拓扑图，仿真数据扩展 `ap_x / ap_y`（AP 固定坐标）、`user_x / user_y`（UE 坐标），单位 m；或由后端内置静态坐标表，CSV 不变。
> 完整字段规范见 [docs/data_dict.md](docs/data_dict.md)。
