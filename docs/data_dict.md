# AI-NetTune 项目数据字典

> 文件说明：本文件为团队开发契约文档，定义 CSV 仿真网络数据集字段规范。**后端、仿真脚本、前端开发均以此文档为准。**

## 字段规范（v2.3：18 列）

| 列名 | 含义 | 单位 | 数据类型 | 取值/枚举 | 说明 |
|---|---|---|---|---|---|
| timestamp | 采样时间 | yyyy-MM-dd HH:mm:ss | datetime | 2026-01-01 00:00:00 ~ 2026-01-03 23:59:00 | 指标采样时间戳 |
| ap_id | 接入点编号 | - | str | AP-01、AP-02、AP-03 | 无线接入点ID |
| ap_x | AP 横坐标 | m | float | 120/380/260 | AP 部署位置（热力图/拓扑用） |
| ap_y | AP 纵坐标 | m | float | 220/160/350 | AP 部署位置 |
| user_id | 用户编号 | - | str | UE-01 ~ UE-03 | 终端用户ID |
| ue_x | UE 横坐标 | m | float | 20 ~ 480 | 用户实时位置 |
| ue_y | UE 纵坐标 | m | float | 20 ~ 430 | 用户实时位置 |
| rsrp | 参考信号接收功率 | dBm | float | -140 ~ -60 | 无线信号强度，数值越大信号越好 |
| sinr | 信干噪比 | dB | float | -10 ~ 30 | 信号质量，越高越好（v2.3 起限幅） |
| throughput | 吞吐量 | Mbps | float | 0 ~ 150 | 用户下行速率 |
| latency | 时延 | ms | float | 8 ~ 80 | 端到端网络延迟 |
| packet_loss | 丢包率 | % | float | 0.1 ~ 22 | 数据包丢失百分比 |
| prb_usage | PRB利用率 | % | float | 10 ~ 98 | 无线资源块占用率 |
| scenario | 场景标签 | - | str | 校园、商场、体育馆 | 物理部署地点场景（v2.3 起为中文，与后端白名单一致） |
| network_status | 网络状态 | - | str | normal、congestion、weak_coverage | 网络运行健康状态：正常/拥塞/弱覆盖 |
| retransmission_count | 重传次数 | 次 | int | 0 ~ 8 | 与丢包率、时延正相关（故障深度分析） |
| traffic_demand | 业务需求 | Mbps | float | ≥ throughput | 潜在业务需求，≥ 实际吞吐量 |
| active_users | 活跃用户数 | 人 | int | 3 ~ 11 | 与 AP 负载正相关 |

## 命名规范（全队统一，后续变量一律按此）

- AP 编号：`AP-01`、`AP-02`、`AP-03`（**连字符**，不是下划线）
- 用户编号：`UE-01` ~ `UE-03`（**连字符**，v2.3 实际生成 3 个 UE）
- 网络状态枚举：`normal` / `congestion` / `weak_coverage`（小写）
- 场景枚举：`校园` / `商场` / `体育馆`（中文，与后端 `VALID_SCENARIOS` 精确匹配）

## 故障注入说明（v2.3 新增，演示用）

生成器内置 4 段固定故障窗口，用于接口2 故障诊断/证据链/闭环演示：

| 时间 | 目标 AP | 类型 |
|---|---|---|
| 2026-01-01 10:00~12:00 | AP-02 | 弱覆盖 |
| 2026-01-01 20:00~22:00 | AP-01 | 拥塞 |
| 2026-01-02 14:00~16:00 | AP-03 | 弱覆盖 |
| 2026-01-03 09:00~11:00 | AP-01 | 拥塞 |

故障时段内强制 UE 接入故障 AP，使异常采样占比超过研判阈值（弱覆盖占比 >30% 或 RSRP<-105 且 SINR<5 → 覆盖故障；拥塞占比 >25% 或 PRB>90 → 网络拥塞）。

## 使用约定

1. CSV 数据文件必须包含以上全部 18 列，列名与上表完全一致；
2. 后端接口返回的字段名与上表一致（见 `api.md`）；
3. 前端展示、图表字段映射以 `timestamp`、`ap_id`、`user_id`、`ap_x/ap_y/ue_x/ue_y` 及 KPI 列名为准；
4. 后续新增字段必须先更新本文档，再同步后端/前端。
